# 海克斯大乱斗数据服务设计

## 目标

为微信小程序提供国服海克斯大乱斗的版本化查询 API，第一阶段覆盖英雄、强化符文、版本统计和数据来源；暂不依赖实时玩家战绩查询。

## 数据分层

### 静态资料

英雄、装备、强化符文名称、描述和图标来自 Riot Data Dragon、CommunityDragon 或经过授权的数据集。静态资料按版本保存，不能覆盖历史版本。

### 统计资料

登场率、出现率、组合和出装统计来自已授权的国服数据集或用户贡献数据。每条统计记录必须包含版本、样本量、来源和更新时间。胜率字段允许为空，不能在没有合规数据时自行推导或展示。

## 版本发布流程

1. 人工准备已授权的静态资料和统计 JSON 文件。
2. 使用导入命令按版本写入数据；新版本进入 `collecting` 状态，导入时校验 ID、样本量和比例值。
3. 人工审核来源、样本量和异常变化。
4. 使用发布命令检查英雄、强化符文和统计数据，并在事务中将版本改为 `published`。

自动下载和 staging 流程尚未接入，需要确定数据供应方和授权方式后实现。

版本上线初期样本不足时，只发布静态资料；统计数据达到预设样本量后再发布。

## API

- `GET /healthz`：服务健康检查
- `GET /api/v1/patches/latest`：获取最新已发布版本
- `GET /api/v1/champions`、`GET /api/v1/champions/{id}`、`GET /api/v1/augments` 和 `GET /api/v1/combos`：已发布版本的数据查询，支持指定历史版本

## MySQL 约定

- MySQL 8.0+、InnoDB、`utf8mb4`。
- 统计百分比使用 `DECIMAL(8,5)`，存储比例值，例如 `0.12345`。
- 所有统计表包含 `patch_id`，所有导入数据记录 `source_id`。
- 发布操作使用事务；失败时不改变当前 `published` 版本。
- 英雄和强化符文的静态资料按版本保存快照；双英雄组合按版本和英雄对保存。

## 数据合规

保留数据来源、授权说明、文件哈希和导入日志。对外展示时提供来源链接、样本量、更新时间和版本号，并遵守数据供应商及 Riot 相关开发者政策。
