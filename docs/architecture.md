# 海克斯大乱斗数据服务设计

## 目标

为微信小程序提供国服海克斯大乱斗的版本化查询 API，第一阶段覆盖英雄、强化符文、装备、版本统计和数据来源；暂不依赖实时玩家战绩查询。

## 数据分层

### 静态资料

英雄、装备、强化符文名称、描述和图标来自 Riot Data Dragon、CommunityDragon 或经过授权的数据集。静态资料按版本保存，不能覆盖历史版本。

### 统计资料

登场率、出现率、组合和出装统计仅覆盖国服海克斯大乱斗，来自已授权的国服数据集或用户贡献的该模式对局。不得以国际服、普通大乱斗、斗魂竞技场或云顶样本替代。每条统计记录必须包含版本、样本量、来源和更新时间；接入采集时需保存地区和模式并在聚合前校验。胜率字段允许为空，不能在没有可靠数据时自行推导或展示。

## 版本发布流程

1. 人工准备已授权的静态资料和统计 JSON 文件。
2. 使用导入命令按版本写入数据；新版本进入 `collecting` 状态，导入时校验 ID、样本量和比例值。
3. 人工审核来源、样本量和异常变化。
4. 使用发布命令检查英雄、强化符文、装备资料和已有统计数据，并在事务中将版本改为 `published`。

静态资料支持 `go run ./cmd/importer fetch --version <Data Dragon 版本>`：下载固定版本的英雄、技能、KIWI 强化符文和装备资料，转换为导入 JSON，保留原始文件与来源哈希。`sync --version <版本>` 自动增量迁移、下载并导入资料。发布前检查技能覆盖，默认等待人工审核后发布；可显式使用 `--publish`。图片保存固定版本外部地址，不下载到服务器。没有定时更新任务。国服对局统计采集与 staging 流程尚未接入，需要确定数据供应方后实现。

版本上线初期样本不足时，可只发布静态资料。已发布快照不可覆盖；仅允许给完全没有装备或技能资料的历史版本一次性补入对应资料。统计采集后的快照更新流程仍需实现。

## API

- `GET /healthz`：服务健康检查
- `GET /api/v1/guides`：版本化编辑玩法、英雄与海克斯联动、出装阶段及选择理由
- `GET /api/v1/champions/{id}/skills`：读取 MySQL 中预先导入的版本化技能简介，未导入时返回 404
- `GET /api/v1/patches/latest`：获取最新已发布版本
- `GET /api/v1/champions`、`GET /api/v1/champions/{id}`、`GET /api/v1/augments`、`GET /api/v1/items` 和 `GET /api/v1/combos`：已发布版本的数据查询，支持指定历史版本

## MySQL 约定

- MySQL 8.0+、InnoDB、`utf8mb4`。
- 统计百分比使用 `DECIMAL(8,5)`，存储比例值，例如 `0.12345`。
- 所有统计表包含 `patch_id`，所有导入数据记录 `source_id`。
- 发布操作使用事务；失败时不改变当前 `published` 版本。
- 英雄、强化符文和装备的静态资料按版本保存快照；装备资料额外固定 `KIWI` 模式，静态属性与对局统计分开；双英雄组合按版本和英雄对保存。
- 编辑玩法存于 `gameplay_guides` 的结构化 JSON，所有英雄、海克斯和装备引用由导入器校验，当前版本缺少引用则整次导入回滚。审核后编辑内容可独立于已发布图鉴维护，按版本与玩法标识 Upsert；来源与导入哈希仍保存。
- `champion_patch_skills` 按版本和英雄保存称号、定位、被动及 Q/W/E/R 技能和固定资源版本。查询服务不请求外部资料源。
- 图鉴和技能图片 URL 随资料入库，客户端直接读取固定版本的 Data Dragon 或 CommunityDragon 图片。MVP 暂不部署图片托管和 CDN。

## 微信小程序

`miniprogram/` 使用原生 WXML/WXSS，无需 web-view。首页、英雄、海克斯、装备、我的五个入口，另有全局搜索、详情与玩法列表。`lib/core.js` 同时供浏览器 `/mini/` 预览使用，版本查询、搜索筛选、分页、联动解析和本地收藏共用。当前只接静态资料及已审核玩法，界面不展示胜率、选取率或虚构评级。无玩法记录时显示空状态，不从图鉴自动推导推荐。真机与发布需配置 AppID、HTTPS 服务和合法域名。

## 数据合规

保留数据来源、授权说明、文件哈希和导入日志。对外展示时提供来源链接、样本量、更新时间和版本号，并遵守数据供应商及 Riot 相关开发者政策。
