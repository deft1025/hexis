# 对局内决策页面规划

## 核心流程

用户在首页直接搜索或选择英雄，进入该英雄的对局指南。首屏按决策顺序展示：推荐强化符文、出装路线、需要根据局势调整的备选方案。版本、来源和更新时间要易于找到，但不抢占主要内容。

## 页面元素

| 页面 | 首要内容 | 次要内容 |
| --- | --- | --- |
| 首页 | 英雄搜索框、最近查看的英雄入口 | 当前版本和数据状态 |
| 英雄列表 | 英雄图标与名称、推荐符文预览、进入指南按钮 | 胜率、选取率、搜索与排序 |
| 英雄指南 | 2–4 个推荐符文及选择理由；起手、核心、后期装备路线 | 备选装备的触发条件、英雄整体表现、来源与更新时间 |
| 强化符文 | 效果、稀有度、适合的英雄或玩法 | 整体胜率与选取率、搜索与筛选 |
| 装备 | 效果、类型、价格、适合的英雄或场景 | 搜索与筛选；有可靠统计后再显示表现 |
| 英雄组合 | 双英雄配合理由、适用打法 | 胜率与选取率 |

移动端首屏应让玩家在选英雄后直接看到符文和起手装备，不要求横向浏览统计表。列表的样本量和评级不作为主要展示字段；样本量保留在数据审核和详情的来源说明中。

## 数据与接口

现有统计表只有英雄整体统计和符文整体统计，不能推出某英雄适合什么符文。装备资料表、版本快照、导入器和 `/api/v1/items` 已接入，装备图鉴读取真实静态资料。小程序与 `/mini/` 预览已经支持以下结构，当前待补充审核内容：

1. `gameplay_guides` 按版本保存趣味、基础、通用编辑玩法，JSON 中包含适用英雄、核心／备选海克斯、推荐理由及玩法说明。
2. 同一玩法保存出装阶段、装备顺序及选择理由，展示核心与按局势替换的选择；导入器校验全部英雄、符文和装备属于同一版本。
3. 小程序将版本图鉴与 `/api/v1/guides` 关联，英雄详情显示玩法与海克斯联动，符文详情反向显示相关英雄和装备。推荐使用编辑优先级，不使用胜率、选取率或统计评级。

推荐顺位不能直接按整体胜率决定。若使用统计排序，应结合样本门槛和选取率；编辑推荐须标明来源及理由。没有关联数据时展示“待接入”，不要把全局符文胜率或通用装备图鉴伪装成英雄专属推荐。

## 实施顺序

1. 先确定可用的关联数据来源及授权范围，准备覆盖几个常用英雄的样例。
2. 用审核后的原创或获授权内容填充现有版本化玩法表，先覆盖常用英雄，核对触发条件与装备理由。
3. 真机验证原生小程序，配置 AppID 与正式 HTTPS 服务；已有首页直接选英雄、最近查看、收藏、搜索和版本来源。
4. 内容覆盖充足后加入更细的局势筛选，统计数据暂不接入。
