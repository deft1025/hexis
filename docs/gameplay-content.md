# 玩法资料录入

玩法使用 `gameplay_guides` 按版本存储，查询入口 `GET /api/v1/guides?patch=16.20`，支持与其他列表相同的 `limit` / `offset`。只读 API 不提供公开写入；录入通过服务器导入命令。

供本地看效果的公开资料改写样例另存 `gameplay_guide_previews`，不进入已审核查询。预览开关与导入步骤见 [guide-previews/README.md](guide-previews/README.md)。

资料结构见 `guides.template.json`，该文件故意使用占位 ID 和 `reviewed: false`，不会通过导入校验。

| 字段 | 内容 |
| --- | --- |
| `id` | 稳定玩法标识，只能使用字母、数字、下划线、连字符，最多 100 字符 |
| `category` | `fun` 趣味玩法、`basic` 基础思路、`general` 通用玩法 |
| `playstyle_name` | 趣味玩法的流派简称，可选；每条 `fun` 的 `id` 就是独立流派 ID |
| `basic_sections` | 本流派的操作与基础思路，只用于 `fun`；缺省时兼容读取本条 `sections` |
| `references` | 可选补充来源列表，每项 `name`、`url`、可选 `note`；只接受 HTTP(S) 链接 |
| `champion_ids` | 适用英雄；趣味与基础玩法至少一位，通用玩法可为空 |
| `core_augment_ids` / `alternative_augment_ids` | 核心与备选海克斯，引用当前版本 ID |
| `recommendations` | 海克斯及理由，`priority` 为 `core` / `alternative` / `situational`，不展示伪造的 S/A 统计评级 |
| `stages` | 出装阶段、装备 ID、选择理由；审核玩法必须非空，预览样例允许为空并显示资料缺失 |
| `sections` | 玩法说明、触发条件、限制或对局操作，必须非空 |
| `reviewed` | 人工核对版本、模式、效果和引用后设置 `true` |

准备实际资料到自己的 JSON 文件后：

```bash
go run ./cmd/importer migrate
go run ./cmd/importer import --patch 16.20 --kind guides --file ./data/16.20/guides.json --source "原创编辑玩法" --source-attribution "填写作者、审核日期及验证方式"
```

导入器会校验所有引用属于当前版本，包括 `KIWI` 模式装备；错误时整次导入回滚。基础图鉴快照仍不可覆盖，但已发布版本允许维护审核后的编辑玩法，修改以 `id` 为键 Upsert，导入记录保留文件哈希和来源。不含自动玩法生成、自动审核或胜率统计。

玩法手册不按内容分类切换，直接显示玩法卡片与搜索，支持英雄名称、常见别称、玩法和关联海克斯名称。`basic` 仍保留在数据库、全局搜索及英雄详情，不进入玩法手册和首页玩法精选。只有多页时显示分页控件。

英雄详情按玩法展示独立卡片，不再切换趣味玩法、基础思路、海克斯联动三个栏目。列表卡片只展示摘要、核心海克斯和详情入口，英雄通用基础（`basic`）另列。海克斯反向进入英雄时可以保留单条玩法选择，并提供“全部玩法”恢复完整列表。

每张卡片进入自身玩法详情，连续展示“怎么玩、海克斯搭配、装备选择”。`sections` 与 `basic_sections` 合并为阅读顺序，完全重复的段落只显示一次；版本提示集中保留。海克斯 ID 列表与 `recommendations` 合并，同一玩法内每个海克斯显示一次，理由放在对应海克斯下方。只合并展示，不修改数据库内容，不借用其他玩法的操作、理由或装备。相同海克斯跨玩法仍保留各自优先级和理由。

海克斯详情从这些关联反向获取英雄实例，每位英雄卡保留各关联玩法的理由与入口；核心、备选优先级来自内容记录，不是统计排名。默认展示三位，可展开。玩法卡显示当前海克斯的推荐理由，进入详情后查看本条玩法的装备。海克斯列表显示关联英雄/玩法数量，支持“有联动”筛选，未录入资料的海克斯显示待补充。

新版本发布后，旧玩法保留在旧版本，不会自动迁移。重新验证后使用新版引用 ID 导入新版本。截图可以用于分析功能，内容应自行编写或使用获授权资料。
